用户触发 `/synthesize`，表示思辨已结束、双方达成共识，现在要把这段探讨写成文章。

遵循 `.opencode/skills/socratic-essay/SKILL.md` 中的**阶段四（撰写文章）**与**阶段五（审查）**流程：

1. 先回顾本轮苏格拉底式探讨，提炼：核心问题、达成的共识、若干支撑子观点、仍存疑的部分。
2. 列出文章大纲（小节标题 + 每节要点），**先与用户确认或调整大纲**。未经确认不写作。
3. **选择标签与分类时，先查已有值，只在不存在时才新建**：
   - 运行 `npm run list-tag`，在输出中挑选与文章匹配的现有标签；`--tags` 用空格分隔，每个标签须为单个词。
   - 运行 `npm run list-category`，确认期望的分类是否已存在；存在则沿用，不存在才新建。
   - 不要凭空猜测或重复造已有标签/分类。
4. 用户确认后，用非交互模式生成骨架并填入正文：

   ```
   npm run create-post \
     --title "文章标题" \
     --description "摘要" \
     --author "作者" \
     --category "分类" \
     --tags "标签1 标签2" \
     --content "<h1>小节</h1><p>正文...</p>..."
   ```

   - `--content` 为 `<article>` 内的 HTML 片段（中文内容，小节用 `<h1>`，段落用 `<p>`）。
   - 脚本自动分配下一个可用 id 并更新归档。
   - 若想让用户先审阅再归档，追加 `--no-archive`，之后手动运行 `npm run update-archive`。
5. 创建完成后把文件路径交给用户，请其审查文章内容，并等待反馈。除非用户明确要求，不要提交 git。

若本轮讨论尚未充分、或用户未给出明确共识，提醒用户继续 `/opinion-review` 或继续对话，而不是强行成文。
