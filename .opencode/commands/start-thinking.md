用户触发 `/start-thinking`，表示要以一个问题或观点开题，进入苏格拉底式思辨。这是本 skill 的**启动环节**，负责确立问题并开启探讨，直到共识逐渐形成。

遵循 `.opencode/skills/socratic-essay/SKILL.md` 中的**阶段一（确立问题）**与**阶段二（苏格拉底式探讨）**流程：

## 阶段一：确立问题（Ask）

1. 请用户以**一个问题**或**一个观察/观点**开题。若用户只给了主题，用一两个问题帮其收敛成一个可辩的命题（Problem → Question）。
2. 用一句话复述你理解的问题，请用户确认，确保双方站在同一起点上。
3. 先提出你对问题的回答，然后让用户继续提问。

## 阶段二：苏格拉底式探讨（Dialogue）

这一段，**由用户主动发起问题，你进行回答，尝试同意/反驳。**然后由用户继续反驳你的回答，或提出问题。

反复进行"提问 → 回应 → 再追问"的循环，直到共识达成：

- **每次只抛一个核心追问**，避免一次抛出多个问题淹没用户。
- 追问要：
  - 揭示前提与假设（"你为什么这样想？""它隐含了什么？"）
  - 指出矛盾或边界情况（"如果……会怎样？"）
  - 区分概念（"你指的是 A 还是 B？"）
  - 探询反例与另一面
- 认真对待用户的每一次回答，**顺着用户的思路**提出下一个追问，而不是搬出一套预设。
- 控制深度：围绕主题的 3~6 个关键层面探讨即可，避免无休止发散。
- 观察用户何时开始**改述、补充、修正**自己的观点——那是共识逐渐形成的信号。

注意：上述追问不一定必要。仅当**你在某个观点上没有确定的立场时才抛出问题寻求用户建议。**如果你有观点，不要提问，而是直接说你的看法。

- **不明确的社会事实必须查证**：当讨论涉及现实世界的社会事实（如某项政策、统计数字、历史事件、特定组织/人物的主张、社会现象描述等）且你不确定其准确性时，**不要凭记忆臆断**，应使用 `web_search` 等搜索引擎工具查询并核对这些信息，再基于查证结果继续探讨。若无法查到可靠来源，明确告知用户信息存疑。对"事实"与"观点/解释"也要区分——前者需要查证，后者属于思辨本身。如果你不知道什么是明确什么是不明确，请**每个 request 都查证一次相关概念**。

## 结束与交接

- 当双方不再有新的分歧，用一段话**总结达成的共识**（论点 + 若干支撑子观点），并**等待**。
- **不要自行进入写作**。成文须由用户显式触发 `/synthesize`（将共识落笔成文）或 `/opinion-review`（审查思辨过程并给出反驳）才会进行。
- 在用户触发之前，只停留在对话与共识阶段，不写文件。
